# Living Routes HK — 产品逻辑重构

## 一句话

**坐车听一段属于这条街的故事，到站后留下自己的记忆，下一次打开时听到更适合自己的内容。**

产品不是三个平行功能（导览、社区、日志），而是一条闭环：

```text
选择兴趣 → 坐车听故事 → 到达地点 → 拍照/录音/写感受
                                      ↓
                         AI 生成私人回忆片段
                                      ↓
                         更新兴趣画像与下一次推荐
```

## 进入项目前的伦理声明

用户进入兴趣问卷前，先阅读并签署简明的 `Community Ethics Statement`。声明包含四项承诺：知情同意、署名选择、纠错与撤回权、合理分享收益，并明确 AI 只负责辅助转写、翻译和改编，公开发布仍需人工审核。

首次签署只用于说明平台原则，不替代居民或其他贡献者对每条录音、照片和故事的单独授权。MVP 中签署记录只保存在当前浏览器会话，不上传服务器。

## 三类导览内容

### 1. Heritage Facts / 官方史料

- 来源：古物古迹办事处、政府、博物馆、公开档案等。
- 语气：准确、简洁、适合在巴士上收听。
- AI 作用：在已核实资料范围内改写、翻译和按剩余时间压缩。
- 必须显示来源。

### 2. Local Voices / 街坊声音

- 来源：真实居民、旧住户、店主、长者中心参加者的授权录音。
- 核心资产：原始声音本身，而不是 AI 假造的“老人故事”。
- 录音方式：普通手机、WhatsApp 语音或由学生/社工代录。
- AI 作用：降噪、转写、地点/主题整理、翻译、生成字幕和短版摘要。
- 没有真实录音时，只能标记为“Demo adaptation / 演示改编”，不能伪装成居民亲述。

### 3. Culture Bites / 城市趣闻

- 来源：经过核实的公开报道、人物采访、书籍或文化资料。
- 可以包括演员、歌手、运动员、作家与某条街、某间店、某个社区的公开趣闻。
- 重点是“和这个地点有关的文化连接”，不是未经证实的八卦。
- 使用普通旁白或获得授权的声音；不能未经许可克隆在世名人的声音。
- 必须显示“公开资料整理”及来源。

播放器只展示这三种内容中的一个或两个推荐选项，不再把所有内容都塞进 Official / Civilian 双线。

## 个性化规则

用户的兴趣不是简单选择一次后就结束，而是一个逐渐更新的 profile：

- 初始兴趣：Architecture、Culture、Food、Nature。四项均为“兴趣主题”，避免把内容来源、叙事主体和兴趣类型混在同一组选项中。
- 行程中行为：跳过哪类故事、听完哪类故事、选择哪种语言和时长。
- 行程后内容：照片地点、文字关键词、录音主题、用户主动选择的标签。
- 推荐结果：下一站故事类型、长度、语言、相关地点和社区帖子。

第一版只需使用可解释的规则，不必声称已经有复杂机器学习模型：

```text
摄影照片 + 建筑关键词 → 下一段优先推荐建筑细节 / 今昔对照图
食物照片 + “想吃/味道” → 推荐附近街坊食店与饮食史
人物回忆 + 粤语录音 → 推荐 Local Voices 与同主题街区故事
```

### 已确认的首页偏好决定（2026-09-28）

首页第二题改为 `What are you interested in?`，并提供四个可多选项：

```text
Architecture · Culture · Food · Nature
```

MVP 中，这组偏好保存在用户设备上，不公开显示，也不改变社区帖子的审核状态。它同时服务于两处：

1. **导览个性化**：同一地点优先选择或突出与偏好相关的讲解角度。
2. **社区信息流个性化**：社区帖子使用相同的四类主题标签，优先展示与用户偏好相关、并且位于当前路线或附近地点的内容。

社区推荐不得只显示用户已经选择的主题。首版使用可解释规则，并保留一定比例的跨主题内容，避免形成单一兴趣的信息茧房：

```text
推荐顺序 = 兴趣匹配 + 路线/地点相关 + 新鲜度 + 跨主题探索
```

后续数据结构方向：

```js
profile.preferences = ['architecture', 'culture']
post.topics = ['culture', 'food']
story.topics = ['architecture', 'nature']
```

帖子主题可以由发布者主动选择，并由 AI 根据文字、图片和地点提出标签建议；AI 建议不应在用户确认前替代用户选择。

## 行程后记忆 Studio

这是导览结束后的独立页面，不是社区信息流的一个小功能：

1. 用户选择照片、文字或自己的声音。
2. AI 生成私人回忆录：标题、地点章节、字幕和短文。
3. 可选生成一张“记忆明信片”或 10 秒竖屏片段；默认私人。
4. 用户明确点击分享后，才生成 Community Post。
5. 分享时显示“AI-assisted memory”以及用户是否授权公开。

比赛 MVP 先稳定完成：**照片/文字 → 私人回忆录**。AI 图片或视频属于展示加分项，不应成为核心依赖。

## Hackathon MVP 取舍

演示只需要让评委看到四个可信瞬间：

1. 同一地点根据兴趣切换 Heritage Facts / Local Voices / Culture Bites。
2. 播放一段真实授权的粤语录音；没有录音的卡片明确写 Demo adaptation。
3. 用户上传照片和一句感受，生成私人旅行回忆录。
4. 这条回忆被转成兴趣信号，下一站推荐发生变化。

暂不把真实 WhatsApp 后端、实时名人音色克隆、自动公开视频发布作为 MVP 必需条件。
